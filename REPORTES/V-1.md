## 1. Qué se hizo

**Nuevo**

- `studio/frontend/src/board/vanguardia/combinador.ts`
  - `combinar(semilla, referentes, herramientas, reglas, restricciones, gustos?)` → `Combinacion` con 2-3 referentes distintos, una herramienta, una regla y una restricción.
  - PRNG mulberry32 sembrado con FNV-1a: la misma semilla devuelve la misma combinación, incluido `azarPuro`.
  - Si la primera tirada cae por debajo de 0.2, **todo** se elige uniforme (azar puro); si no, referentes, herramienta y regla se eligen con peso.
  - El peso de un referente posterior se multiplica por el peso del par con cada referente ya elegido: `peso(ref) × peso(ref, previo)`.
  - `azarPuro` viaja en el resultado para que la proporción del 20 % sea medible sin mirar dentro del PRNG.
- `studio/frontend/src/board/vanguardia/gustos.ts`
  - `Gustos` = `{ version: 1, referentes, reglas, herramientas, pares }`; lo ausente pesa 1.
  - `like(gustos, combinacion)` suma 1 a los referentes, la regla, la herramienta y cada par; `nope()` resta 1. Siempre recorta a [0.2, 5] y nunca muta la entrada.
  - `conGustos(proyecto, gustos)` y `gustosDeProyecto(proyecto)`: la memoria vive en el objeto del proyecto. **No se llama a `localStorage` en ningún punto.**
  - `gustosAJson()` / `gustosDesdeJson()` y `ARCHIVO_GUSTOS = 'gustos.json'` para exportar e importar.
  - `normalizarGustos()` acepta JSON viejo o parcial, descarta valores no finitos y recorta.
- `studio/frontend/src/tests/vanguardia.test.ts`
  - 5 tests: determinismo, variedad con otra semilla, recorte de pesos, 20 % en 10 000 tiradas y persistencia/export.

## 2. Contrato

```ts
combinar(
  semilla: string,
  referentes: readonly ReferenteFuente[],   // { id, nombre, etiquetas }
  herramientas: readonly HerramientaFuente[], // { id, nombre }
  reglas: readonly ReglaFuente[],           // { id, nombre }
  restricciones: readonly RestriccionFuente[], // { id, texto }
  gustos?: Gustos,
): Combinacion
```

```ts
interface Combinacion {
  semilla: string;
  referentes: string[];   // ids de tarjeta, 2-3, sin repetir
  herramienta: string;    // id
  regla: string;          // id
  restriccion: string;    // texto
  azarPuro: boolean;      // esta tirada ignoró los pesos
}
```

Decisiones que conviene saber:

- **El id del referente es obligatorio**: `Referente` no lo lleva, y los gustos deben sobrevivir a un cambio de nombre. El llamador pasa el id de la tarjeta junto a la ficha.
- **La restricción se elige uniforme**: la skill solo pide pesos por referente, regla, herramienta y par. No se inventó un quinto peso.
- **La cantidad (2 o 3) se decide con la semilla**: con 2 referentes siempre salen 2; con 3 o más, 50/50. No se añadió un parámetro que la fuerza.
- **La herramienta solo aporta `id` y `nombre`**: el combinador no importa su Vista ni ejecuta el registro de herramientas en tiempo de ejecución.
- **Errores explícitos**: menos de 2 referentes, o cero herramientas/reglas/restricciones, lanza un `Error` con el motivo. No se devuelve una combinación a medias.

## 4. Límites que quedan (dichos, no tapados)

- **Sin UI y sin cableado al proyecto**: `conGustos` devuelve un proyecto nuevo para que el mecanismo de guardado existente lo persista, pero V-1 no conoce ese mecanismo ni añade el campo al modelo de proyecto. Eso es V-2.
- **Sin `reglas.ts`**: las reglas entran como datos `{ id, nombre }`. Las funciones puras de disposición que pide la skill no se implementaron aquí.
- **Restricciones sin id en el resultado**: se guarda el texto, que es lo que se muestra. Si más adelante se quieren pesos por restricción, habrá que añadir `restriccionId` y migrar gustos.
- **Par multiplicativo**: `peso(ref) × peso(par)` puede crecer mucho antes de elegir. No se recorta el peso de selección, solo el almacenado; es deliberado para no aplastar la señal de los pares.
- **Prueba estadística de una sola máquina**: el 20,12 % es determinista para estas semillas, no una garantía matemática. El test acepta ±2 puntos, como pedía el encargo.
- **`gustos.json` aún no se descarga**: existe el texto y el nombre del archivo; el botón de exportación necesita UI.
