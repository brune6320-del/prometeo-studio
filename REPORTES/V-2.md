## 2. Contrato

```ts
type PiezaCollage = { id: string; aspecto?: number };

type TamanoLienzo = { ancho: number; alto: number };

type PiezaColocada = {
  id: string;
  x: number;
  y: number;
  w: number;
  h: number;
  rot: number;
  z: number;
  recorte?: { x: number; y: number; w: number; h: number };
};

function aplicarRegla(
  id: string,
  piezas: readonly PiezaCollage[],
  semilla: string,
  tamano: TamanoLienzo,
): PiezaColocada[];

function combinar(
  semilla, referentes, herramientas, reglas, restricciones,
  colocacion: Colocacion,
  gustos?: Gustos,
): CombinacionColocada;
```

Ejemplo de uso:

```ts
const combinacion = combinar(
  semilla,
  referentes,
  herramientas,
  REGLAS,          // las 7 reglas reales
  restricciones,
  { piezas, tamano: { ancho: 1200, alto: 900 } },
);

combinacion.disposicion; // regla elegida ya aplicada
```

Decisiones:

- **`recorte` es una ventana normalizada** `{ x, y, w, h }` dentro de la imagen original (0-1), no un booleano. Es lo que necesita un recorte real en la Vista; hoy nadie la interpreta todavía.
- **La semilla se separa por regla**: cada regla usa `generador('<regla>:<semilla>')`. Misma semilla y misma regla, misma disposición; reglas distintas no comparten flujo.
- **El aspecto es opcional**: si falta, se asume 1. Se acota a `[0.2, 5]` para que una imagen extrema no rompa el lienzo.
- **Los ids repetidos se descartan** y el orden de entrada se conserva, igual que en el combinador.
- **Un lienzo inválido lanza error** (ancho/alto no finitos o ≤ 0). No se devuelve una disposición a medias.
- **No se interpretan colores, formas ni textos**: el contrato pedido no los lleva. Bauhaus no pinta rojo/amarillo/azul; eso queda para la Vista.

## 3. Las 7 reglas

| Regla | Geometría implementada | Semilla |
|---|---|---|
| **Dadá** | Piezas grandes, rotadas entre −22° y 22°, superpuestas; `recorte` aleatorio; `z` barajado. Su caja rotada puede salir hasta un 10 % por cada lado. | Sí |
| **Bauhaus** | Retícula de 12 columnas; filas de bloques sin solape; `rot = 0`; `x/y/w/h` en múltiplos de `ancho/12`; recorte centrado si el hueco no respeta el aspecto. | Sí (spans) |
| **Constructivista** | Bloques en tensión sobre una diagonal de 30° (el eje de composición, no la rotación de las piezas); tamaños grandes y solape. | Sí |
| **Fluxus** | Partitura en el tiempo: cada pieza ocupa un pulso de izquierda a derecha, en dos alturas alternas; `z` marca el orden. | Sí |
| **Situacionista** | Deriva: recorrido aleatorio con pasos sembrados; cada pieza cae en un punto del recorrido y queda acotada al lienzo. | Sí |
| **Suizo** | Rejilla estricta a la izquierda, una sola alineación, anchos de 4-7 columnas, mucho aire y `rot = 0`. | Sí |
| **Irene** | Primera pieza grande como archivador; el resto son miniaturas a la derecha; la última es la más pequeña (la «mono»). | Sí |

Nota: la skill también habla de texto suelto, instrucciones numeradas, mapa NYPL y mono fotografiada. Eso no cabe en `{ id, x, y, w, h, rot, z, recorte? }`; aquí solo se resuelve la geometría.

## 5. Límites que quedan (dichos, no tapados)

- **Sin validación visual**: 4 tests prueban geometría, no que bauhaus parezca bauhaus ni que Irene parezca un archivador.
- **Bauhaus sin color ni forma**: el contrato no lleva `color` ni `forma`, así que el rojo/amarillo/azul y el círculo/cuadrado/triángulo no están. Recomiendo resolverlo en la Vista, no en `reglas.ts`.
- **Dadá no crea texto**: solo coloca las piezas recibidas; el «texto suelto» tendría que entrar como pieza de texto desde fuera.
- **Fluxus no escribe instrucciones ni tiempos**: el pulso está en la `x`; el texto no existe en el contrato.
- **Situacionista no usa NYPL maps**: dibuja la deriva sin mapa de fondo.
- **Irene no distingue una mono real**: la última miniatura es la más pequeña, pero no hay imagen ni etiqueta de mono.
- **Constructivista no gira las piezas**: la diagonal de 30° es el eje de colocación; `rot` sigue en 0 para no romper los límites. Si quieres bloques girados, es una decisión visual y un cambio de contrato.
- **Bauhaus en lienzos muy bajos**: si el alto no alcanza para una fila de una celda, el alto de fila se reduce fuera de la retícula; `x` y `w` siguen alineados. No ocurre en 1200×900 ni en los tamaños normales.
- **`recorte` todavía no lo consume nadie**: es dato preparado para la Vista.
